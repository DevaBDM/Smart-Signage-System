# Smart Signage — Shared Anthias Device Agent (`Device/`)

This package contains the **canonical, deduplicated implementation** for Raspberry Pi devices running the Anthias-based agent (previously duplicated across `Device1/` and `Device2/`).

## Why this exists

`Device1/` and `Device2/` were byte-for-byte duplicates except for three values:
- `DEVICE_ID`
- `DEVICE_NAME`
- `LOCATION`
- `SERIAL_PORT`

Every bug fix had to be applied twice. This package solves that by keeping one shared codebase and moving per-host overrides into thin `config.py` files.

## Architecture

```
pi-scripts/
├── Device/                          ← this package (shared code)
│   ├── socket_client.py             ← canonical Socket.IO agent
│   ├── content_sync.py              ← canonical content sync agent
│   ├── brightness_control.py        ← display brightness control
│   ├── Arduino_connection.py        ← serial helper
│   ├── config_defaults.py           ← shared defaults
│   ├── config.py                    ← TEMPLATE for per-device overrides
│   ├── run.py                       ← shim showing how to launch
│   ├── emergency_fallback.mp4
│   ├── disconnection.png
│   ├── no_content.jpg
│   ├── socket-signage.service.tpl
│   └── content-sync.service.tpl
├── Device1/                         ← unchanged (legacy standalone)
├── Device2/                         ← unchanged (legacy standalone)
└── Device3/                         ← MPV-based agent (genuinely different)
```

## Files

| File | Purpose |
|------|---------|
| `config_defaults.py` | All shared constants — server URLs, serial settings, timeouts, asset paths. |
| `config.py` | **Template.** Shows how a per-device `config.py` should import defaults and override `DEVICE_ID`, `DEVICE_NAME`, `LOCATION`, `SERIAL_PORT`, and `SERVER_URL`. |
| `socket_client.py` | Socket.IO client: heartbeat, sensor loop, emergency detection, token management, device registration. Imports from `config`. |
| `content_sync.py` | HTTP polling agent: syncs content from the server to Anthias via its REST API. Imports from `config`. |
| `brightness_control.py` | Reads sensor file (`/tmp/signage_sensors`) and adjusts display brightness with `brightnessctl`. No config imports. |
| `Arduino_connection.py` | Serial helper for Arduino handshake. No config imports. |
| `run.py` | Shim that adds `../Device` to `sys.path` and calls `socket_client.main()`. Copy to a per-device folder. |

## How per-device overrides work

When a device adopts this package, it keeps only two files in its own folder:

```python
# Device1/config.py
from config_defaults import *

DEVICE_ID = 1
DEVICE_NAME = "Pi-Display-1"
LOCATION = "Floor 1"
SERIAL_PORT = "/dev/ttyS0"
SERVER_URL = "http://192.168.56.1:5000/api"
```

```python
# Device1/run.py
import sys, os
_device_dir = os.path.dirname(__file__)
_shared_dir = os.path.join(_device_dir, "..", "Device")
sys.path.insert(0, os.path.abspath(_shared_dir))

from socket_client import main
if __name__ == "__main__":
    main()
```

When `run.py` executes:
1. `sys.path` is updated so `Device/` is findable.
2. `socket_client.py` does `from config import ...`.
3. Because the working directory is `Device1/`, `config` resolves to `Device1/config.py`.
4. `Device1/config.py` imports shared defaults from `Device.config_defaults` and overrides the host-specific values.

## Token file location

Both `socket_client.py` and `content_sync.py` now read `TOKEN_FILE` from `config` instead of hardcoding a path relative to themselves. Each device's `config.py` should set:

```python
TOKEN_FILE = os.path.join(os.path.dirname(__file__), ".device_token")
```

This keeps each device's token in its own folder.

## Systemd services

Templates are provided (`socket-signage.service.tpl`, `content-sync.service.tpl`). When installing on a Pi:

1. Copy the template to `/etc/systemd/system/socket-signage.service`.
2. Update `WorkingDirectory` and `ExecStart` to point to the **per-device folder** (e.g. `/media/signageDevice1/run.py`).
3. Run `systemctl daemon-reload && systemctl enable --now socket-signage`.

## Migrating an existing device

1. In `Device1/` or `Device2/`, keep only:
   - `config.py` (thin override)
   - `run.py` (shim)
   - `.device_token` (generated by server)
2. Optionally keep the asset files (`emergency_fallback.mp4`, `disconnection.png`, `no_content.jpg`) in the per-device folder, or symlink to `Device/`.
3. Update systemd `.service` files to point to the per-device `run.py`.
4. Restart the service.

## Smoke test after migration

```bash
# On the Pi
sudo systemctl restart socket-signage
sudo journalctl -u socket-signage -f
```

Expect:
- `Serial port opened successfully` (or retry messages if Arduino is disconnected)
- `heartbeat` emissions every 30s
- No duplicate `heartbeat_loop` threads

## Notes

- `Device/` is a **blueprint** for now. `Device1/` and `Device2/` are left untouched until you decide to migrate them.
- `Device3/` (MPV-based) is genuinely different and is **not** covered by this package.
- Asset paths in `config_defaults.py` point to the `Device/` folder. Per-device configs should override these if assets are stored locally.
